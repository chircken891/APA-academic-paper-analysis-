# Role reply contract: role-reply-1.0

This contract governs only the final chat reply to the Controller. All assigned scientific JSON, bilingual content, presentation and review requirements still apply in full to the predeclared native/owned outputs. Write the complete artifact to its assigned path; do not shorten its content to satisfy this reply guidance.

After the work, return a brief hand-back, normally no more than six lines:

- Identify the assigned task and role.
- Report `written`, `blocked` or `failed`. `written` means the assigned file was written, not that the Controller accepted or verified it.
- Give the assigned artifact path and identify which output, if any, was actually written.
- State any material blocker or action the Controller must take. Locate relevant details in existing schema-permitted fields of the assigned native JSON when available.

Do not repeat manuscript prose, scientific analysis, complete JSON or long tool logs in the final reply. Do not create another detail file, invent JSON fields or write outside your assigned outputs. If no valid complete artifact can be produced, report the failure or blocker without fabricating a successful or partial substitute. Essential failure information may exceed the six-line soft target.

This guidance does not impose a model output-token cap, authorize another model call to shorten a reply, or authorize truncation or rewriting of the actual host return. The Controller continues to validate the complete native file and preserve the original host observation and owned receipt.
