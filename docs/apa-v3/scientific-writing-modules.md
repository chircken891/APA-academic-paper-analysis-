# 科研写作模块与语言协作

适用于 APA V3 新未绑定运行及明确授权的科研写作任务。Nature 指导组织内容，Humanizer 改善表达；两者在既有 Writer 的同一次写作中使用，不增加角色或模型调用。

## 适用规则

先确定任务是解释已发表论文，还是撰写作者自己的论文，再选择文章类型、语言和当前模块。模块表是按需使用的写作指南，不是每篇文章必须逐项填满的模板。

规则分为三层：

1. 通用写作原则规定模块承担的任务、论证顺序和信息分工。
2. 研究类型的报告规范规定该设计需要报告什么，如随机试验、观察性研究、系统综述；在适用时从 EQUATOR 等来源选择。
3. 目标期刊当前投稿要求决定文章类型、字数、摘要格式、模块位置、附件及声明要求。具体限制需要使用时再查官方要求，不把技能中的数字或例文当成固定规则。

Nature Skills 是第三方写作指导，其中部分建议来自发表论文的归纳，不能称为 Nature 官方规范。没有指定目标期刊时采用通用原则，不默认按 Nature 主刊格式写作。

## 按需查阅

Writer 请求只携带本页的路径与版本指纹，不附上整张模块表。先根据当前任务定位模块行，再读取有关的使用边界；已经明确的常规部分不重复加载。下表是参考索引，不是需要逐项核对的验收清单。

原创科研写作需要更细的指导时，在任务准备阶段按 Nature Writing 的 manifest 选择对应 section；已有稿件的局部润色选 Nature Polishing 的对应 section。标题页、声明和投稿信等按 submission-package 入口选择。只把本次确实需要的片段纳入任务，不运行整套技能工作流。已冻结的 APA 请求只读取其绑定的项目参考页。

## 全文模块

| 模块 | 任务、顺序与必要内容 | 使用边界 |
| --- | --- | --- |
| 标题与短标题 | 用研究对象、核心问题或有依据的主要发现标识文章；短标题保留辨识信息。 | 准确、具体，避免口号及无证据的首创表述；不为缩短而丢失关键条件。 |
| 标题页与作者信息 | 按期刊要求组织文章类型、作者顺序、单位映射、通讯作者、ORCID、贡献注释及字数等。 | 仅使用作者确认的信息；匿名稿与身份信息按要求分离，不推断作者资格或顺序。 |
| 摘要 | 从问题与目的进入设计或方法，交代主要结果，再给出有边界的结论；保留必要数值、比较条件和不确定性。 | 结构式或非结构式及篇幅由期刊决定；不加入正文没有的发现。已发表摘要不以此规则重写。 |
| 关键词 | 选择能准确检索研究对象、设计、方法及主题的词；领域要求时使用受控词表。 | 数量和格式依期刊，不堆砌宽泛热词，不冒充原论文关键词。 |
| Highlights、意义声明与编辑摘要 | 每项集中表达一项具体发现或贡献，必要时说明对目标读者的意义。 | 按期刊或用户需求生成；数量和字数不固定，不复制摘要或拔高应用价值。 |
| 图形摘要与目录图 | 用简明的研究对象、过程及主要结果说明研究主线，保证图中文字和箭头含义清楚。 | 仅在需要时制作；不能凭示意图暗示未经验证的机制，也不自动增加绘图角色。 |
| Introduction | 从相关背景收束到尚未解决的问题，说明既有工作的不足及其后果，最后明确本研究目的和解决路径。 | 引用用于建立问题，不罗列文献；创新程度、研究目的和后文结果相互匹配。 |
| Related Work | 按问题、方法或证据组织已有研究，比较其贡献与限制，说明当前研究的位置。 | 是否独立成节取决于文章类型；不把引用数量当作充分性，也不把阅读笔记当系统综述。 |
| 理论背景与假设 | 定义关键概念、理论关系和成立条件，说明推导如何导向可检验的预测或研究问题。 | 区分理论假设、事先假设和事后解释；不能把观察相关性改写为机制证明。 |
| Methods：设计与对象 | 依实际研究流程交代设计、场景、时间、对象或材料、选择标准、样本来源及研究过程。 | 只描述实际采用的做法；必要细节缺失交回科学角色，不使用一般方法默认值替代。 |
| Methods：操作与测量 | 说明每一步为何需要、输入是什么、怎样操作、输出什么，以及测量定义、设备或软件和适用条件。 | 有助复现和理解的细节进入适当位置；已知方法引用不能替代本文的关键改动。 |
| 统计与计算分析 | 交代分析单位、变量、模型、比较或估计目标、假设、缺失数据处理、不确定性与适用的敏感性分析。 | 区分预设与探索性分析；不补造检验、样本量依据、阈值、参数或未实施的稳健性分析。 |
| Results | 按研究问题组织发现；每段说明比较对象和条件、主要结果及定量支持，连接相关图表。 | 描述发现与解释分工明确；正文突出影响理解的结果，避免逐格复述表格或只报显著性。 |
| Discussion | 先回答研究问题，再解释主要发现，与既有研究比较，讨论替代解释、适用范围及有依据的意义。 | 综合结果而非重述 Results；因果、机制及推广强度不得超出设计和证据。 |
| 局限与未来研究 | 从作者已有处理进入剩余缺口，说明影响哪项判断、哪些结论仍成立；仅在有依据时提出对应后续研究。 | 区分作者局限、分析判断、所供材料限制与报告差异；核对反证，移除已解决或无依据的批评。缺报告不等于未做分析，不固定条数或自动要求补分析。详见科学合同的 Interpretation/Appraisal。 |
| Conclusion | 用与研究问题对应的结论收束全文，保留必要条件及最重要的意义。 | 是否独立成节依文章类型；不引入新结果、不复制摘要，不强行添加总结段。 |
| 图与图注 | 图呈现关键关系；图注说明对象、分面、符号、组别、单位及理解结果所需的样本量、误差或统计定义。 | 图注与正文互补；说明图中实际内容，不猜测原图未给出的标注。阅读笔记保留可用原图入口。 |
| 表与脚注 | 用清楚的行列、表头、单位和分母组织比较，脚注定义缩写、统计量、例外与缺失值。 | 必要时保留原表图像及解释，不为展示而全表重录；正文不重复全部数字。 |
| 公式与符号 | 在使用处定义符号、单位、条件及公式作用，连接输入、操作与解释。 | 区分原文公式、等价转写和教学示意；不将解释性表达称为作者采用的模型。 |
| 参考文献 | 引用与所支持的背景、方法或结论相邻，使用真实来源和目标格式，优先明确直接来源。 | 外部方法背景不能证明本文采用了具体参数或获得了某项结果；不凭记忆编造书目信息。 |
| 附录与补充材料 | 放置确有需要的详细推导、扩展方法、额外结果等，说明与正文的关系，并保持可定位引用。 | 解释主线必需的信息不能仅藏在附件；本项目正文范围不因出现该模块而自动扩大到补充材料。 |
| 致谢、经费与作者贡献 | 按实际贡献和资助事实说明支持及分工；采用 CRediT 时依据作者提供的信息映射。 | 不发明贡献、资助编号或获得致谢者同意的事实，不将助手写作过程当研究贡献。 |
| 伦理、参与同意与发表同意 | 按研究对象与期刊要求说明适用的批准、豁免及同意事项，区分三者。 | 只用有依据的声明和编号；不能把未提供信息写成“不适用”或默认已批准。 |
| 利益冲突与相关稿件披露 | 陈述实际的相关利益、预印本、会议版本或关联稿件情况。 | “无冲突”、原创性及全体作者同意均需真实依据，不替作者确认行政事实。 |
| 数据、代码与材料可用性 | 说明真实存放位置、标识符、访问方式、限制及适用的许可条件。 | “可申请获取”不能改成“公开可用”，不能补造仓库、版本、登录号或许可证。 |
| AI 使用声明 | 按目标期刊当前要求及实际使用情况说明工具、用途和作者责任。 | 不隐瞒要求披露的使用，也不把语言辅助写成研究方法；措辞不能替代实际事实。 |
| 首次投稿附件 | 按目标期刊选择投稿信、匿名稿、报告规范表、权限文件及其他所需材料；投稿信说明发现、证据和读者相关性。 | 不默认生成整套附件，不自动提交；推荐审稿人及相关行政信息需真实来源和作者确认。 |

## 阅读笔记的适配

APA 的主要任务是解释已发表研究，不能替作者重写一篇原创论文。使用上表理解各模块的信息职责，再按读者理解顺序组织笔记；允许合并模块或沿原论文结构展开，不强制 IMRAD。

已发表标题、摘要、图表说明及其他明确引用的源文本保持原样；中文译文忠实于原意，不用 Humanizer 增删其科学内容。新的说明段落与原文、译文及外部方法背景清楚区分。

正文可以用“研究背景”“研究设计”“主要结果”“研究局限”等简洁主题标题，具体时补充研究对象。标题不承担整段解释，不写成对读者的指令、聊天问句或“主题：长串解释”。更改标题时维护实际锚点链接。

标题页、作者贡献、伦理声明、投稿信等属于原创写作或投稿任务的规则范围；阅读笔记仅在理解研究或用户需要时提及已报告的信息，不创建虚构的投稿身份与声明。

最终仍交付具备图表、知识链接及导航的 Obsidian 笔记。Writer 受控输出用于内部交接，不另生成一份纯文字阅读入口；仅在用户明确要求样例时另存预览。

## 同一次写作中的分工

1. Integrator 将科学角色的发现、解释、重要限制及已补足内容交给两语 Writer，并保留本文事实与方法背景的区别。
2. Writer 先按 Nature 的模块职责、论证顺序和段落衔接组织内容；已有稿件局部修改采用 Nature Polishing，不无故重构全文。
3. 在同一次写作中采用中文 Humanizer-zh 或英文 Humanizer，删去套话、机械排比、假对比及空泛收尾；stss 处理多余的内部核对叙述和自我说明。
4. 保留专业术语、关键条件、事实、数值及确定程度，不将科研讲解改成聊天语气；不以“更自然”为由弱化必要限制或删去重要解释。

不能靠润色修复的信息缺口交回既有科学角色：Evidence 找回原文，Methods 补方法与概念，Results 补关键结果与图表关系，Integrator 合并后回交 Writer。沿用已有定向补缺范围、预算与截止时间，不让 Writer 凭常识补写事实。

仍只做一次整体审查、必要时最多一次局部复核。技能中的逐项清单、术语台账、逐主张核对、模拟审稿或多轮润色不自动接入项目；它们不形成新的交付物或完成门槛。

## 加载与版本

运行使用项目中纳入版本管理的本参考页。Writer 请求只携带短指引以及本页路径、SHA-256 和字节数，恢复时沿用同一绑定；完整模块表不注入每次请求，也不动态读取可变的全局技能。更新技能后，只将需要的规则整合到本参考页；历史绑定、来源指纹和已有候选不追溯改写。

全局安装的 Nature Writing、Nature Polishing 与 Nature Shared 是按需参考材料。后续只加载与任务、研究类型、模块和目标期刊有关的片段，不每次读取整包。现有缺口处理规则优先于技能中“留占位符后结束”的默认做法。

需要期刊精确限制或研究类型规范时，查询对应官方来源，记录本任务实际采用的要求；这不授权寻找本篇补充材料、递归查文献或扩大论文运行来源范围。
