# 主动补缺与方法文献追溯

适用于新运行中明确冻结补缺权限的 reading-first 流程。当前工程路径为 `D:/文献知识库/.worktrees/apa-v3`。既有已绑定运行的来源权限、预算和历史结果不自动改变。

## 从缺口到讲解

只有妨碍理解研究问题、设计、方法或关键结论的问题进入补缺。现有材料尚未处理属于待办工作，不能写成“资料不存在”。普通不影响理解的细节不单独派发，不用补缺清单取代连贯讲解。

| 情况 | 负责人和处理 | 应进入讲解的结果 |
| --- | --- | --- |
| 正文、图表已有，但抽取/传递遗漏 | Evidence 找回相关原页，Results 恢复关键结果及图表条件 | 原文支持的事实、关系与必要出处 |
| 本篇简写并引用原始方法文献 | Methods 定向阅读该引用的相关方法部分 | 原理、输入输出、关键步骤、适用条件及在本文中的作用 |
| 理解所需背景仍不足 | Methods 按权限查相关权威方法资料或官方文档 | 可直接帮助理解的背景，明确区别于本文实际做法 |
| 作者未报告或相关材料不可取得 | 对应科学角色记录真实处理结果 | 已知做法、具体不确定性、受限判断/复现/比较，以及仍可成立的内容 |

方法文献里的常见默认阈值、实现或训练设置不是本文采用这些设置的证据。外部方法资料只能作为背景；本文事实必须回到本篇已登记材料。只有本篇明确提供的采用关系才可用于解释其报告的做法，不能由通用方法反推未报告参数。

## 一次集中补缺与有限修订

科学角色先在自身正常阅读中解决可解决的问题。Integrator 将剩余重要问题按来源/研究对象合并，安排一次集中补缺，避免相同问题多人重复查找；同一句“阈值是什么”涉及不同方法时不能合并。

补缺角色按其原职责返回实际 owned 输出。Integrator/Controller 将解释和具体限制合入两语共享上下文；Writer 在指定受影响章节写出完整解释。小型消费定位只说明内容应进入何处，不作为语义正确性的证明。已有整体审查同时判断说明是否真实有用，无额外审计调用。

如果成稿审查发现材料本身缺少必要科学解释，先交 Evidence/Methods/Results 修复，再请求受影响 Writer 更新；如果已有材料充分、只是写作遗漏，则直接沿 Writer 局部修订。两种情况均保留原先一轮整体审查、最多一次局部复核，未受影响的角色和内容不重跑。

仅增加状态、给出链接或让读者自行查找不算补缺完成。若材料确实不可得或作者未报告，形成具体、有用的边界说明即可结束该补缺；仍然影响关键结论的未知不能被改判为科学完成。

## 来源、授权与预算

新运行提案默认列入需要的定向补缺范围，并在批准后冻结：先用现有正文/原页/图表，再追溯直接引用的原始方法；必要时查相关权威方法源或官方文档。范围内不逐条重复请求许可。不得自动寻找补充材料、递归展开引用链、付费购买资料或扩大为整套论文分析。

冻结的是允许的检索范围，不要求未来发现的每份方法材料在运行开始前已知文件哈希。新材料在实际取得后单独保存并登记身份、原引用/网址、版本、局部读取范围和字节哈希，受控接收后绑定至该次上下文版本。保留原始 PDF、MinerU 及历史产物，禁止覆盖它们或把外部背景混入本篇事实来源。

保留原授权截止时间和调用上限。补缺与写作/复核调用共同消耗 Controller 被分配的原预算，已经发生的科学角色调用须先从原总额度扣除；配置补缺上限不产生额外额度。原有语言阶段上限仍有效，已用预算在中断后不清零。没有剩余额度时保留已完成解释并说明具体剩余影响，不重开整个流程。

## 接入与验证

运行入口复用 `scripts/v3/reading-first-runtime.mjs`、现有 host 派发和 owned store。代码接口及示例在项目技能的 Controller 调用链说明中维护。初稿前补缺成功后才释放 Writer；晚期科学补缺成功后才释放相关 Writer 修订。已有无补缺策略的绑定继续走原路径，不获得新增来源权限。

真实方法资料的发现、获取和内容阅读由既有科学角色通过获准的工具完成；运行库负责范围、接收、共享上下文和有限调用顺序，不另建爬虫或下载服务。自动检查只能验证结构和来源分类；解释是否准确完整由既有的一次成稿审查判断。

本次工程只使用合成材料及模拟 host 返回验证接口；不因合成测试通过而宣称真实论文缺口已经解决。
