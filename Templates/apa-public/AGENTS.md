# APA project rules

- Before cloning, extracting, installing or writing configuration, require the user to choose or explicitly confirm the absolute project folder. Never default to the current chat folder or a child such as `outputs/APA`. Recommend setting the chosen project folder as the agent's working directory. Use that root explicitly in commands that accept a root argument; a different working directory does not change the target. Do not re-ask for the same already confirmed target. Keep task scratch files below that repository's `.tmp/<task>/`.
- Recommend a drive with enough free space for PDFs, parsed text and images, run records, notes and any selected local runtime, with room for growth. Once the user agrees to use the selected repository as the working directory, use the three bundled skills in its `.agents/skills/`; they are project-local by default. If the user keeps skills outside the project scope, explain that discovery and rule scope may differ and global loading may affect other everyday tasks. Any migration or removal of existing global copies requires separate authorization.
- Read root `README.md`, `SETUP.md`, and `docs/CONFIGURATION.md` before first use. Use the repository `apa-setup` skill to inspect or change personal configuration.
- Use `academic-paper-analysis` for paper reading and continuation. Use the repository `apa-query` skill for writing-oriented library questions, clues, thematic synthesis, candidate ideas, source lookup, requested section drafting, and topic or writing-project saving and selected updates; load its specific procedures only for that work.
- Personal configuration belongs only in ignored `config/apa.local.json`. A public export deliberately contains no personal answers. Missing required settings block a new configured reading; existing bound runs keep their frozen configuration.
- Installation permission is not permission to choose configuration. Requests to create, complete, change or import configuration, including "configure it for me" or "configure for this agent", require generating and opening the HTML setup page for the user to choose host dispatch, models and reasoning effort, output folders, parser location, presentation, writing guidance and optional query preferences. Conversation questions cannot replace the page. If the host cannot open it, provide its full path and wait for the user to open it and submit choices. Inspection, export and removal of explicitly selected settings do not require the page. "You decide" or "use all recommendations" cannot authorize agent-selected answers.
- Detection results, historical defaults, recommendations and the only available option are not user answers. Preserve unanswered settings as missing or unchanged; never fill them to reach `ready`. Explain incompatible settings and ask the user to choose a supported value or defer; never silently switch to `follow-main`.
- Build operations only from the user's selections. Show the target folder and before/after differences, obtain explicit application confirmation, then use the existing CLI and read back the result. A complete user-supplied operation with an explicit apply request needs no repeated questions about the already selected target and fields. Never write personal configuration or operate the page to fabricate user choice or approval. Host detection reports are not saved configuration choices.
- MinerU, its global launcher, Better Embedded Canvas and five companion writing skills are selected by default in setup. The user can clear any selection. Selecting either Nature skill adds the internal `nature-shared` dependency to the final preview. Before installation, report available and missing items, exact targets and effects for the final selection. Obtain installation authorization separately from configuration approval. BRAT, Claudian, Dataview and Templater are checked only.
- On repeated host inspection, first locate and check the current agent's prior profiles and self-owned adaptations against the current host evidence. Reuse valid results and investigate only changed or missing items. Store each new report under an unoccupied `.tmp/apa-setup/<owner>/<detection-id>/`; the inspector validates the supplied declarations and does not discover or merge old profiles itself. New self-owned adapters belong in `config/backups/<owner>/adapters/<id>/`, and configuration exports and host-setting backups in `config/backups/<owner>/`. Preserve existing and other agents' adaptations. Preparing a patch does not authorize enabling it or changing host settings.
- Accept paper PDFs by user-provided filesystem path. Keep the paper and its supplementary materials in `Clippings/` under the user's chosen repository and reference existing files there in place. During preparation, copy inputs from outside `Clippings/` into that directory under their original filenames. If an existing file has the same name and different bytes, stop and ask the user how to proceed. Keep source files local. Use `Raw/` only as temporary storage for supplementary literature traced by AI within the approved reading scope. Any location change for a registered source requires an explicitly approved path migration that checks affected runs and references and preserves frozen records. If the user directly uploads a PDF to invoke APA, refuse analysis in that conversation before reading, extracting, parsing or dispatching paper roles. Ask them to save the PDF and open a new conversation with its path, explaining that this avoids putting the PDF body in the conversation context and saves usage. Do not save the attachment and continue in the same conversation.
- Preserve source files, human notes, evidence and unrelated changes. Reading candidates do not authorize publication. Dependency installation, external writes, publication and Git operations require explicit user authorization.
- Use the V3 reading-first workflow and its source/evidence boundaries. Deliver coherent bilingual Obsidian notes. Keep scientific limits and unresolved issues visible; synthetic tests do not establish real-paper acceptance.
- For new configured readings, the actual source language selects one Writer, followed by Translation into the other language, the optional Reading Editor and one overall review. Do not ask for a preferred writing order. Freeze selected models, host dispatch, paths and enabled writing guidance for that run. Committed historical runs are read-only and are not resumed; a binding outside the current versions is refused with `READING_BINDING_RETIRED`.
- Treat `.apa-v3/phase22/COMMITTED.json` and its paired manifests as the registered identity and source inventory. Query, graph and knowledge reuse read the current Markdown of registered Wiki notes; saved prose edits take effect immediately. Rebuild the query index in memory per request and report actual paths, anchors and content fingerprints. Diagnose unavailable objects and mark partial results; reject damaged commit pairs and verify original sources independently.
- 查询以论文写作为目的，综合与构思默认给出可用于写作的表述，整节起草按请求触发。确定性检索、知识地图和参考文献导出不调用模型；综合、构思、起草及指定节审稿意见每次沿用一个配置任务，写作指导与过度表述审查在同一任务内完成。接口是否可用以当前实现和技能说明为准。
- 保留证据底线：不编造来源与数值，区分作者结论与跨篇推断，区分“库内未见证据”与“有证据表明不存在”；库内综合不宣称系统综述。外部新颖性核对仅在用户对具体想法明确开启并给出预算后运行，来源在执行前确认，其余查询不自动扩展文献；外部论文只作为待读线索。
- 默认只读，专题和写作项目仅按明确保存或更新请求准备候选，正式写入沿用精确批准的受控事务。写作项目使用独立身份、revision 与实际来源依赖，保留 Personal Notes 和旧版本，默认不进入图谱；相关提示只供用户选择更新范围。
- Preserve unrelated current note edits during publication. Extend shared nodes from their current prose, retain human sections, and recheck actual dependencies and write targets before promotion. Rebase approved shared-node additions onto current prose within the documented allowed differences; show changes outside that scope for renewed approval. For new publications, copy the approved files individually, back up only targets that will be overwritten, and update registration, index and graph metadata. Save a signed manifest and this publication's output files for interruption recovery; do not create complete previous-vault snapshots or whole-package reconstruction recipes. Registered research-map Canvas files use their current JSON; their recorded hashes describe publication-time observations. Other registered non-Wiki objects retain hash verification. Missing files, invalid identities and damaged Canvas JSON block only operations involving those objects, with a specific path and reason. New files, moves, deletions and identity changes retain the existing controlled registration rules.
- Single-paper and batch publication use the same serial queue. Save each approval request under the run's `publication/` before waiting for the consumer lock, then enqueue and drain from the waiting session. Keep entries queued while a live process holds the publication lock, check every 5 to 10 seconds, and report the owner and elapsed wait each minute. Prepare the latest generation and dry-run before creating a fresh maintenance window. Preserve actual approvals and completed transaction checks. Unsupported inputs require a specific error and a stop; do not create a temporary bypass driver.
- A user-specified single factual correction confirmed against the original source can use publication `user_corrections`: list the note path, unique before/after replacement, source location and user's words for each language. Show it in the exact inventory and apply it in the same approved transaction, preserving original review bytes without more model calls or reviews. Values, symbols, coefficients, units and direction words are eligible; paragraph arguments, maps and navigation changes retain the `user-revision` and local-review route. A limited candidate still follows the official continuation process before publication.
- Freeze `current-shared-nodes-1.0` for reading bindings. Verify the commit pair to establish registration, then read current shared-node prose and record the paths and fingerprints actually reused. Unrelated note edits do not block candidate materialization. Previews include current text for referenced existing knowledge and labeled navigation pages for earlier papers; preview assets do not become this paper's publication outputs. See `docs/apa-v3/reading-first-obsidian.md`.
- Use the four APIs in `scripts/v3/reading-session.mjs` for new reading sessions and recovery. Dispatch only after the independent `reading_preflight` passes. New configured runs freeze `configured-reading-2.2` and, when Editor is selected, `reading-editor-1.4`, following `prompts/v3/reading-editor-1.4.md`. Each language note embeds its own research-map Canvas and links to the full board. The three columns cover all registered steps and findings, their relationships, and claims grounded in the accepted prose. Register both Canvas files as presentation assets under `Figures/<run_id>/`. Default graph scope follows the registered notes. Preserve fixed module headings, headings no deeper than level three, and expanded contents, method entries and captions. Keep one overall review and at most one local recheck. Repair from the accepted Editor baseline only within the located review scope. Persist rejected repairs as `completed_with_limits`.
- New role, revision and enrichment dispatches bind `dispatch_message_profile:'instruction-path-1.0'`: the message contains only the frozen instruction-file path and must equal it after trimming outer whitespace. Structured arguments remain exact; the Controller checks the instruction fingerprint at observation and acceptance. Existing-handle continuations retain their frozen messages, and old bindings keep their original validation.
- Refresh research maps for committed notes through the approved `map-refresh` maintenance transaction using existing registered material. Read current Canvas JSON and preserve x, y, width and height for unchanged node IDs; lay out new nodes automatically. Update the committed registration and index in the same transaction. An explicitly approved layout restoration targets only the selected nodes and language.
- Put reusable modules in `scripts/`, tests in `test/`, documentation in `docs/`, final authorized notes in `Wiki/`, and assets in `Figures/`. Keep analyzed papers and their supplementary materials in `Clippings/` and temporarily store AI-traced supplementary literature within the approved reading scope in `Raw/`. Method nodes belong in `Wiki/methods/`.
- Run the smallest relevant tests. Report changed files, validation and remaining limitations. Do not install dependencies or make global changes as a side effect of configuration.
- Report project acquisition, dependency installation, user-selected configuration saved, and readiness separately. Readiness does not establish successful model calls, PDF parsing or paper acceptance.
