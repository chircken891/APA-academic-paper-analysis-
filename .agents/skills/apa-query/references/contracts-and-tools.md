# Query and topic contracts

All executable paths are relative to the selected APA repository. Inspect live exports and schemas for programmatic integration; private planning files are not required. Configuration and companion guidance are described in [writing.md](writing.md) and the sibling [apa-setup skill](../../apa-setup/SKILL.md).

| Need | Repository entry and boundary |
| --- | --- |
| Search registered papers | `node scripts/apa-query.mjs search --query "terms" [--vault-root path]`; no run ID or reading configuration. `queryLibrary` reads current Markdown within the verified registration inventory and refreshes its in-memory index. Carry `generationId` from search into `readQuerySource`; original-resource identity is checked separately. Use current content hashes and partial-result diagnostics. Identity verification does not verify a scientific claim. |
| Prepare one configured evidence answer | `node scripts/apa-query.mjs request --input <json-file-or-dash> [--vault-root path]`; dash reads stdin. JSON carries question, actual mainSession, supportedModelPairs and hostCapabilities. `prepareLibraryQuery` emits one current-session/native-delegation task; a native-delegation task carries `dispatch:{tool,arguments}` built from the saved `host` section (Codex shape without one); the caller must consume it and read the selected evidence. `executeLibraryQuery({...inputs,executeHost})` invokes the supplied native adapter once and requires its real answer. Preparation is not execution; unknown/unsupported explicit models fail without fallback. A reported host identity mismatch returns `ok:false/identity_mismatch`, preserving requested/observable identities and the diagnostic answer without retry. Unobserved identity remains unknown. |
| Read a registered original source | `node scripts/apa-query.mjs source --paper-id <id> --generation-id <id> [--source-id <id>] [--vault-root path]` returns the verified path and available locators, not PDF text or a scientific verdict. Use query-returned IDs and the existing PDF reader only for the necessary range. |
| Inspect query configuration | `node scripts/apa-setup.mjs inspect --capability query`; no reading dependencies are probed. Default inspect capability remains reading. `models.query` and `query` answer preferences are optional; see [configuration](configuration.md). Prepared query/update tasks consume resolved preferences, with updates retaining the saved topic language. The model defaults to follow-main; actual model support comes from the current host, not file readiness. |
| Save a requested topic candidate | `node scripts/apa-query.mjs topic-save --input <json-file-or-dash>` calls `prepareTopicSave` in `scripts/v3/topic-library.mjs`. Explicit save intent, answer and actual adopted sources are required; it uses the existing candidate root without full reading dependencies or a mandatory model call. A candidate is not formally published. |
| Inspect topic sources | `node scripts/apa-query.mjs topic-sources --topic-id <id> --generation-id <id>` expands a committed topic's adopted paper/source versions through `readTopicSources`. Keep topic identity separate from paper identity; unavailable or historical originals do not become current source verification. |
| Publish a prepared topic | `prepareTopicPublication` in `scripts/v3/topic-publication.mjs` produces the owned topic review; capture/rebuild registration uses the existing controller trust and `phase22-publication` transaction. Review/dry-run/apply/recover stay in `scripts/v3/bilingual.mjs`, with `phase24-topic-1.0` profile and exact review/output approval. Single-language topic review is not a reading-first scientific receipt. |
| Inspect topic update hints | `node scripts/apa-query.mjs topic-hints --generation-id <id>` / `getTopicUpdateHints` use existing terms and source relationships, with zero model calls or topic writes. Paper commit results carry hints; hint failure never reverses the committed result. |
| Prepare and execute a selected topic update | `topic-update-request --input <json-file-or-dash>` / `prepareTopicUpdate` bind topicId/baseRevision/generationId/selectedSources/question plus the existing query model and host fields. `executeTopicUpdate({...inputs,executeHost})` consumes one native task. Input excludes personal notes and unselected sources. Output separates actual answer/execution identity from task preparation and recomputes the body/dependency diff. |
| Save an executed update candidate | `topic-update-candidate --input` uses original save fields, `saveIntent:'update'`, topicId/baseRevision and execution from the completed execution_record; optional resolvedEventIds/eventResolutions retain explicit handling evidence. Stable identity, next revision, original owned review/registration and exact approval remain required. |
| Register an explicit source change | `source-change --input` / `prepareSourceChange` prepare correction/replacement/withdrawal metadata with explicit changeIntent, exact target and reason. A serialized candidate can be re-prepared with `prepareTopicPublication`; serialized review/plan cannot grant ownership. Only original approved transaction commit makes the event visible. |
| Cancel a pending topic operation | `topic-cancel --input` / `cancelTopicOperation` require operationId/candidateFingerprint; unregistered candidates also name candidatePath. Registered cancellation consumes `createTopicCancellationGrant` from the existing trusted Controller and its original key. Trust anchor is the trusted-process/environment channel, not input JSON. Uses the same publication lock, retains candidate files and refuses already committed/in-progress operations. |

Preparation, actual host execution and exact approved publication are separate outcomes. The original Controller and transaction handle topic writes; a serialized review or a skill instruction cannot supply publication authority.

## 写作导向接口

| 需要 | 入口 |
| --- | --- |
| 盘点和知识地图 | inventory；landscape [--canvas]；dossier --node；clues --from。详见 synthesis.md。 |
| 综合、构思 | request --input 中提供 mode:themes/dossier/compare/clues/ideas，沿用一次配置任务。 |
| 按节起草或批注 | draft --section related-work/introduction/discussion --input；review --input。使用 projectId 或显式临时 writingContext。 |
| 写作项目候选 | project-save／project-update-request／project-update-candidate --input，独立 project_id，受控事务详见 writing-project.md。 |
| 参考文献 | export-refs --project-id --format bibtex/ris/both，只返回JSON中的content，调用方按授权保存。 |
| 结构校验 | validate-result --input {generationId,mode,output,materials}，不调用模型。 |
| 可见稿呈现 | render-result --input {mode,output,outputPath?}，零模型；outputPath为仓库相对目标Markdown路径。构思保留来源、近邻、风险／投入与收敛分类；草稿在主张后显示强度和归属。review原文保留。 |
| 外部新颖性 | novelty --input，准备不联网；network_authorized:true执行，phase:assess消费已保存记录。预算与来源须先明确授权。 |
