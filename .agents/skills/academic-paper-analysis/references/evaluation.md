# V3 evaluation and acceptance

For new configured readings, configuration validation and dependency availability precede dispatch. They do not prove parser fidelity or scientific acceptance. See [current role/content contracts](../../../../docs/apa-v3/current-contracts.md); existing bound runs retain their frozen qualification and do not reload personal configuration.

## New reading-first standard

For new unbound `reading-first-1.0`, acceptance prioritizes a complete, coherent explanation of existing material and consistent bilingual meaning. Sixteen topics guide content; per-item signing and per-fragment reverse grounding are not gates. A single post-render overall review checks critical source nodes only (main conclusions, crucial design, conclusion-changing numbers/formulas/table relations), with at most one localized recheck of material repairs. Minor format/citation-style imperfections and unreviewed ordinary details do not block. Preserve material unresolved issues, original source limits and actual review scope. No separate source-first/scientific-audit/pre-render parity call is required. A pending handoff is not a pass or publication permission.

The standards below remain relevant to their declared historical packages and to genuine provenance/authorization; do not use them to restore exhaustive checks to the new default or to relabel older results under the new rule.

## Keep these judgments separate

| Judgment | What is actually established |
| --- | --- |
| Software/contract check | Named local behavior on the tested fixture or saved input. |
| Parser evaluation | Registered sources, reference method, denominator, actual execution and comparison outcome; source-assisted corrections remain attributed to that method. |
| Scientific reading | Supported claims, quantities, sixteen obligations, applicable research threads and explicit missing-material effects. `partial` can remain after local checks pass. |
| Role execution and review | Actual task/return/saved artifact bindings, exposure to upstream content, and observed ownership/revision behavior. |
| Final reading presentation | Completeness and coherent reader-facing explanation on the final rendered/merged text; pre-render parity or populated headings alone do not establish this. |
| Native reading observation | Actual applicable Obsidian pages, assets and navigation; synthetic graph behavior does not establish real-paper readability. |
| Handoff | Exact type/version, valid dependencies, qualification and intended consumer; pre-render status alone is not downstream acceptance. |
| Phase acceptance | Current requirement matrix and approved criteria; document counts, test totals and GSD progress percentages are insufficient. |
| Publication | Separately approved reviewed content and output inventory through the supported deterministic transaction. |

Use actual schema enums in structured files. In reporting, distinguish `not_run`, actual failure/rejection, `not_comparable`, and quality acceptance. An unsupported format diagnosis does not become a successful parse; a missing attachment does not disappear from the original corpus. Preserve the Phase 21 registered twelve-paper/six-class scope and denominators unless an explicit scope decision changes the contract.

## Distinguish representation from scientific evidence

A string/normalization mismatch is not automatically a scientific omission. Conversely, a matching number or repaired glyph does not establish matching units, population, conditions, formula meaning or causal strength. Separate source defects, parser defects, reference mistakes, mapping/serialization defects, unsupported formats and missing scientific context before choosing a fix.

Preserve frozen native/baseline scores and raw outputs. If an approved non-blind source-assisted reference or candidate correction improves a comparison, record the new lineage and retain the earlier failure. Do not attribute the improvement to the original parser or an independent backend. Reference adoption, candidate repair, scientific revision and criterion changes are distinct actions with their own applicable scope.

Negative evaluation is useful evidence but not quality acceptance. Representation-only/capacity-only/preparation inputs are not scientific handoffs. An authorized source-evidence handoff may retain a failed or unmet parser requirement; its scientific qualification and downstream consumer support must be assessed separately. Do not relabel these inputs as another supported type.

## Select sufficient checks

Run checks for the actual change, with a named failing case first when feasible for a behavior defect. Reuse valid historical source/role/recovery evidence rather than repeating all papers or all agents. Widen verification only for new failures, cross-module effects or unresolved risk. For large storage changes, include actual save/reload/consumer use; memory-only equality is insufficient.

Use ASTRA-E01–E10 when applicable: authorized continuation, interruption/recovery, tool-result association, scientific attribution, package rejection, receipt binding, ownership/revision, source injection, stale approval and evidence accounting. Retain the narrower level of each observation: offline fixture, actual host action, real-paper source review, independent review and human gold are not interchangeable.

Record new checks in the active run or phase's existing ledger, not a frozen historical ledger. Include case/command or actual session/agent identifier, relevant input/instruction/output fingerprints, expected versus observed result, pass/fail/not-run/blocked status, evidence level and remaining owner. Refer to existing bindings instead of creating redundant inventories. Synthetic receipts/transcripts remain test fixtures.

## Downstream and stopping decisions

Phase 21 supplies evaluated parsing, collaboration evidence and qualified per-paper handoff. Phase 22 owns bilingual rendering and transaction compatibility; the inserted Phase22.1 owns reading-presentation remediation and final-page completeness/readability/native acceptance; Phase 23 source bridges/candidates; Phase 24 human augmentation/documentation; Phase 25 integration and delivery assessment. Verify the live roadmap rather than using this description as permission to start those phases.

Before downstream consumption, check the exact producer/consumer schema pair, revision, source and configuration bindings, scientific qualification and parser disposition. Preserve limitations in both languages and reject stale receipts. Local `publishable: false`, preparation-only status or unsupported consumer compatibility cannot be cleared by renaming an artifact or copying `Eval/` to `Wiki/`.

Close a scoped task at its achieved result or genuine stopping condition. If the user ends work on a source-limited paper, preserve its supported reading, unresolved critical questions, failed parser result and absent handoff. Work closure alone does not prove scientific or parser success. If the user separately approves a phase-scope revision, record that scoped closure and retained unmet capabilities while leaving runtime qualification unchanged. Reopen work only for a new relevant reason and authority.

For final-page decisions, use [presentation-and-reading-review.md](presentation-and-reading-review.md). Scope the claim to the observed representation: a valid Writer view can still produce a poor or incorrect rendered page. Include the rendered shared knowledge files and paper-application links in the existing overall review. Attribute reused Controller native observations and their exact sample; distinguish local link/anchor validation, actual GUI observations and unobserved coverage. An engineering or skill test does not count as a real-paper call, native acceptance or phase completion.
