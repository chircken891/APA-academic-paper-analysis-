# APA：论文阅读与 Obsidian 知识库

APA 是一套可配置的论文阅读与 Obsidian 知识库工作流，输出可直接使用的中英文笔记、图表、方法与概念链接。通过 apa-setup 选择角色模型和推理强度，或让角色跟随当前会话；模型名称不限定 GPT。当前安装脚本的环境基线是 Windows x64、Node.js 24、npm 11，以及 MinerU 本地解析路线。

新论文由六个科学角色整合研究问题、设计、方法、结果与局限，再由论文原文语言对应的 Writer 成稿，另一种语言由 Translation 依据该稿翻译，设计部分以一段研究设计概览开头。可选 Reading Editor 补充重点概览、段首加粗小标题、方法/概念目录和分阶段研究导图；模块大标题固定，正文最多三级标题，目录、方法条目和原图注默认收起，读图说明紧随对应图表。完整候选经过一次整体审查，至多一次实质问题局部复核。正式入库需要对精确候选单独批准，只有已提交的 V3 代次进入默认图谱和检索。

> **配置必须由用户在 HTML 页面中选择。** 使用 apa-setup 时，“完善配置”“为我配置”“为某某 agent 配置”等配置请求都必须生成并打开配置页，禁止 AI 自行采用默认值完成配置。导出配置、挖空或去除配置不强制打开页面。首次获取项目还须由用户指定或明确确认项目文件夹；当前会话目录及其子目录不能默认采用。

## 安装与首次使用

配置页面和本地命令可独立使用。角色派发方式由 apa-setup 检测当前宿主，经用户选择采用后保存：例如 Claude Code 使用 `Agent` 工具，Codex 使用协作接口；未保存时按 Codex 方式派发。派发工具不能选择模型的宿主，应向用户说明各角色只能“跟随主会话”，等待用户选择采用或暂缓配置，不能自动改写。填写模型名不会安装模型或接入服务商。以下操作中的“助手”须具备能启动独立子代理的工具和相应模型调用能力；检测与配置成功不证明派发或模型实际可用，以真实运行的返回为准。

### 1. 用户选择项目文件夹，再获取工程

在克隆、解压、安装或写入配置前，先由用户指定或确认**项目文件夹的绝对路径**，明确工程将放在哪里。助手不得自行采用当前会话目录，也不得在其下自选 `APA`、`outputs/APA` 等位置；只有用户明确确认该具体路径后才能使用。已在本会话明确选定的同一目标无需重复询问。

**建议选择剩余容量充足的硬盘存放仓库。** 除工程文件外，PDF、解析文本与图片、运行记录和笔记会持续占用空间；若在仓库内安装 MinerU，还需为其环境、模型和缓存预留空间。根据文献数量和所选组件评估容量，并留出后续增长余量。

已有 Git 时，用户可在 Windows PowerShell 中输入自己选定的项目文件夹路径后获取工程。下面的变量表示工程根目录本身，不是其父目录；输入绝对路径，勿原样填写示例占位符：

```powershell
$apaProjectRoot = Read-Host '请输入你选定的项目文件夹绝对路径'
git clone https://github.com/chircken891/APA-academic-paper-analysis-.git "$apaProjectRoot"
Set-Location -LiteralPath $apaProjectRoot
```

没有 Git 时，可在本仓库页面选择 **Code → Download ZIP**，将工程解压到用户选定的位置，确认包含 `package.json` 和 `scripts` 的实际根目录就是用户选定的项目文件夹，再进入该目录；不要在 ZIP 内直接运行。已有工程则直接确认其根目录，无需重新获取。后面的命令都从这个已确认的工程根目录执行；支持 `--repo-root` 等根目录参数时，助手应显式传入该路径。

**确认项目文件夹后，征得用户同意，将其设为 agent 工作目录，并把三个 APA 技能嵌入该目录的 `.agents/skills/`。** 工程已包含完整技能目录时直接使用；需要补齐时保留技能附带的引用文件及相对路径。可以在该文件夹中新开助手会话，确认宿主能发现项目技能；未自动发现时，让助手读取对应的 `SKILL.md`。

三个项目技能分别为：`academic-paper-analysis` 负责新论文阅读与续接，`apa-query` 负责库内查询、比较及专题保存和更新，`apa-setup` 负责本库配置。**默认仅在项目中提供这三个技能，不安装到全局。** 支持 `$` 技能调用语法的宿主可用 `$academic-paper-analysis`、`$apa-query` 或 `$apa-setup` 调用。

若用户不打算将项目设为工作目录，或不愿将技能迁入项目作用域，助手须明确提醒：技能发现和项目规则的作用范围可能发生变化，保留全局加载方式可能让 APA 规则介入日常其他任务。仍须固定使用用户选定的项目绝对路径。已有全局副本的迁移或移除须单独确认，不随项目获取自动处理。

### 2. 先检测，再安装基础依赖

即使还没有 Node.js，也可以先运行以下只读检测；它不会安装、下载或写入配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup\bootstrap-windows.ps1 -CheckOnly
```

报告是 JSON，可直接交给助手解释。重点看：

| 报告字段 | 怎样判断和处理 |
| --- | --- |
| `checks` 中 `required: true` 且 `status: missing` | 本次安装缺少必要前置；先按该项说明解决 |
| `disk_space` 中 `status: warning` | 低于建议预留空间；结合所选依赖、模型和缓存评估，不作为统一最低空间门槛 |
| `prerequisites_ready` | `true` 表示安装前置已满足，不代表依赖已经装好 |
| `targets` | 将操作哪些目录、哪些项目已存在，以及可能的影响 |
| `next_commands` | 根据所选项目生成的后续命令；审阅后再决定执行，不会自动执行 |

**检测命令正常退出不等于全部就绪。** 基础安装需要 Windows x64、Git、Node.js **24.x**、npm **11.x**。缺少这些软件时，根据报告从 [Git for Windows](https://git-scm.com/downloads/win) 和 [Node.js 官方下载页](https://nodejs.org/en/download) 获取对应版本，安装后重新打开 PowerShell 并回到工程目录，再检测一次。不要直接把“最新版”当作受支持版本。脚本不会替你安装 Git 或 Node.js。

确认报告中的目标并决定安装后，再运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup/bootstrap-windows.ps1
npm.cmd run setup:check
```

默认只恢复本工程的 npm 依赖，不安装 MinerU、全局集成或写作技能。`setup:check` 的基础通过标准是 `core_ready: true`；`parser`、`integration` 和 `obsidian` 的失败项须分别阅读，不能当作基础依赖失败，也不能当作已经完成论文运行。顶层 `ready` 还包含 Obsidian 检查，可能仍为 `false`。本说明使用 `npm.cmd`，避免 PowerShell 将 `npm` 解析为被执行策略阻止的 `npm.ps1`。

### 3. 准备 PDF 解析环境

新论文目前需要可用的 MinerU 环境。**已有环境**可以直接在下一步配置其目录；**需要新安装**时，先检测所选安装的完整前置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup/bootstrap-windows.ps1 -CheckOnly -InstallMineru
```

本工程安装器采用 Python **3.12.x** 作为验证基线，可从 [Python 官方 Windows 下载页](https://www.python.org/downloads/windows/) 获取。[MinerU 官方安装说明](https://opendatalab.github.io/MinerU/quick_start/) 当前给出的包范围为 `>=3.10,<3.15`，具体引擎另有约束；这不等于其他 Python 版本已通过本工程验证。

**20 GiB 是新安装的建议预留值，不是 APA 或 MinerU 的统一最低占用。** 当前脚本选择 Standard、ONNX 小模型和 llama.cpp，[官方模型说明](https://github.com/opendatalab/MinerU#model-engines-with-extras) 列出的模型下载量约 **2 GB**，还需另计 Python 环境、依赖、下载缓存和解析输出，实际大小随版本和组件变化。低于 20 GiB 时预检给出提示，不因此阻止安装；基础安装或复用已有解析环境也不要求额外预留 20 GiB。

按报告处理必要缺项、审阅空间提示并确认所选安装后，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup/bootstrap-windows.ps1 -InstallMineru
```

默认生成 `.runtime/mineru/`，包括 `venv/Scripts/python.exe` 和 `config.yaml`，并下载所需包和模型。多套 Python 并存或自动检测失败时，可在检测与安装两条命令中都加 `-BasePython "实际 Python 3.12 的 python.exe 完整路径"`。遇网络或下载错误，按报错处理后续接，保留已完成内容；安装成功仍不等于真实 PDF 解析验收。

写作技能和全局集成均为可选。首次使用时，用户可以将六项额外写作技能逐项明确选为“不使用”，以后再按 [SETUP](SETUP.md#apa-配套写作技能) 逐项检测和安装；助手不能替用户停用，无需为了生成配置页先装齐它们。

### 4. 打开 HTML，由用户自主选择配置

确认项目目录后，助手先读取已有宿主档案及自有适配说明，再核对当前宿主、会话、派发工具、模型与推理强度。为本次检测选择尚不存在的 `.tmp/apa-setup/<owner>/<detection-id>/` 目录，两个名称使用 kebab-case；将更新后的报告写入其中的 `host-profile.json`，保留旧档案。报告不属于用户配置答案。

使用 apa-setup 完善、新建、修改或导入配置时，**必须生成并打开本次 HTML 配置页，供用户亲自选择、预览并提交操作文件**。“完善配置”“为我配置”“帮我配置”“为某某 agent 配置”等提示均触发此流程；会话讲解只辅助理解页面，不替代页面选择。助手不能代操作页面制造用户选择或确认。宿主无法直接打开本地 HTML 时，须交付完整文件路径并说明限制，等待用户自行打开和提交选择。

“你决定”“全部按推荐”均不能跳过页面选择。检测结果、历史默认值、推荐值和唯一可用选项都不代表用户答案；未回答项保持未配置或原值，不为达到 `ready` 自动补齐。仅导出配置、挖空或去除配置时不要求打开 HTML；去除范围须明确。用户已自行选择并提交完整操作、明确要求应用时，直接核对并应用，无需重新选一遍。

可以将下面这段话交给助手：

> 请帮我安装并配置 APA。先确认我选择的项目文件夹绝对路径，征得我同意后将其作为 agent 工作目录，把三个 APA 技能嵌入项目，不默认安装到全局。先检测环境；安装前展示具体安装项目、位置和影响，等我明确选择。配置时必须生成并打开 HTML，让我自行选择宿主派发、模型与推理强度、输出目录、解析器位置、呈现方式、写作指导及查询偏好。不要代选，即使我说“你决定”或“全部按推荐”也必须保留页面选择。最后核对目标目录和配置前后差异，等我明确确认应用，再保存并回读检查。

带上本次宿主档案检查并生成页面，再用宿主支持的方式打开返回的 HTML。以下 `$apaProjectRoot` 必须是第 1 步用户已确认的项目绝对路径；`$apaDetectionDir` 填写本次已选定并写入档案的实际目录，替换两个占位符：

```powershell
$apaDetectionDir = ".tmp/apa-setup/<owner>/<detection-id>"
npm.cmd run apa:setup -- inspect --repo-root "$apaProjectRoot" --host-profile "$apaDetectionDir/host-profile.json"
npm.cmd run apa:setup -- page --repo-root "$apaProjectRoot" --host-profile "$apaDetectionDir/host-profile.json" --output "$apaDetectionDir/index.html"
```

带档案时，页面增加“运行宿主与派发”一页，由用户选择是否采用检测到的派发方式，模型和推理强度改为从检测结果中选择；`inspect` 的 `host_check` 报告已保存设置与本宿主是否相符。没有档案时也可手动运行不带 `--host-profile` 的同两条命令，此时只能手动填写模型，无法设置派发方式。档案是助手的自我报告，不证明派发或模型实际可用。

`inspect` 和页面展示六项宿主能力自检：按需读取、子代理排查、手动压缩、短回执、科学阶段恢复与阈值自动压缩。运行代理依据当前工具、版本、无凭据配置及必要官方文档调查各项达成方式，并记录证据、步骤和作用范围；找不到时说明查询位置与缺口。已有有效自有适配可验证复用，需要新补丁时由代理在 `config/backups/<owner>/adapters/<id>/` 准备，保留他人的适配；`owner` 根据 agent 身份与归属证据确定，不从所选模型推断。自检不写个人配置，静态达成仍需分别验证真实模型遵守、压缩和续接；阈值由用户填写，宿主设置须预览具体改动并经用户确认后备份、应用和回读，备份保存在 `config/backups/<owner>/`。详见 [配置说明](docs/CONFIGURATION.md)。

再次自检时，先找回当前 agent 的旧档案、补丁说明和已生效设置，与当前工具及版本核对；仍有效的成果继续复用，仅对变化、缺失或失效项补充调查。每次生成独立检测报告，保留旧档案和补丁。`inspect` 只校验本次传入档案的声明，不会自动发现或合并全部旧适配；找回并引用旧成果是运行 apa-setup 的 agent 的职责。补丁未出现在新报告中时，应先核对是否漏传声明。

首次 `inspect` 显示 `exists: false`、`ready: false` 是正常的：公开工程没有任何人的配置答案。`page` 返回 HTML 的完整路径；助手须用浏览器或宿主预览打开本次输出的文件。第一步确认页面所针对的项目文件夹（同页显示本项目自检与宿主能力自检），第二步核对工作目录和 MinerU 解析环境的存放位置，之后才进入“完善配置”“去除配置”“导出配置”三个独立功能；各功能拥有分页、预览和输出，可返回功能选择处切换。

需要配置时选择“完善配置”：宿主派发、知识库查询和阅读设置可顺序切换或直接跳转，切页保留填写内容，第二步勾选的位置修改也在这里一并预览；导入已有备份也在这个功能内。先勾选“修改此项”才能填写，未勾选项目保留原值。“去除配置”单独生成清除操作；“导出配置”单独保存已生效设置，不包含其他功能中尚未应用的填写。助手导出时默认保存至 `config/backups/<owner>/`，用户指定路径或文件名时优先采用；默认文件名为 `apa-config-backup-YYYYMMDD-HHmmss-SSS.json`。

首次分析新论文前，至少完成以下阅读选择；库内查询可跳过这些阅读设置，查询选项未配置时使用默认值：

- **宿主派发方式**：核对检测报告，由用户选择是否采用；检测本身不会授权保存。
- **模型**：按关键判断、专项分析、原文写作、呈现与翻译四组填写，也可逐角色单独设置；涉及六科学角色、中文写作、英文写作、翻译、阅读编辑、独立核验。可以使用“跟随主会话”；指定模型时填写当前宿主实际支持的模型标识与推理强度，不要求名称带有 `gpt-` 前缀。单个科学角色的覆盖可不填，暂不使用阅读编辑时也仍需保存其模型选择。
- **三个输出目录**：分别存执行记录、解析资料和阅读候选，必须在本库内。例如 `Eval/apa-v3/runs`、`Eval/apa-v3/parse`、`Eval/apa-v3/reading`；每次运行自动追加独立编号，不必提前创建每篇论文的子目录。
- **MinerU 位置**：使用上一步安装结果时，运行目录填 `.runtime/mineru`；Python 和配置文件可留作未配置，由运行目录派生。已有环境则填写其实际位置。
- **阅读设置**：选择是否使用阅读编辑；两种语言都会生成。每篇论文的实际原文语言由助手按文献确定，决定原文笔记与译文目录，也决定由哪种语言的 Writer 成稿、Translation 译成另一种语言。
- **六项写作指导**：每项都明确选“启用”或“不使用”。启用时填写实际 `SKILL.md` 文件路径；启用 Nature Writing/Polishing 还须启用 Nature Shared。

以上仅说明选项。用户在页面点击“预览全部已选修改”，确认目标目录和具体修改后，再进入下一步。

### 5. 应用操作，回读确认

页面下载的**操作文件**须经应用才会生效。将下载文件的实际路径交给助手，并说“请应用这份配置并回读检查”；也可以复制完整 JSON 到对话并提出同一请求。用户自行提交完整操作并明确要求应用时，同一目标及范围不必重复询问。导出备份须通过导入预览生成操作文件后再应用。

需要手动应用时，以下示例假定浏览器保存到了用户 Downloads，文件名仍是 `apa-config-operation.json`；请按实际下载位置或改名结果替换：

```powershell
node scripts/apa-setup.mjs apply --repo-root "$apaProjectRoot" --file "$env:USERPROFILE\Downloads\apa-config-operation.json"
node scripts/apa-setup.mjs inspect --repo-root "$apaProjectRoot"
```

应用后的新论文配置门槛是：`validation.complete: true`、所选 `dependencies` 均为 `available`、顶层 `ready: true`。若不满足，报告缺项，让用户选择修正值或另行安排安装检测；不能自主补齐或跳过检查启动论文。`ready` 只证明答案完整和文件可找到，不证明真实模型或解析已运行。出现 `APA_CONFIG_STALE` 时重新读取并展示新差异，由用户确认后生成新操作；不要改旧 JSON 指纹来绕过拒绝。页面继续编辑时也应重新生成，避免读到旧快照。

进度须分别报告，不能用一句“安装完成”替代以下状态：

| 状态 | 表示什么 |
| --- | --- |
| 工程已获取 | 项目文件已放到用户选定的目录 |
| 依赖已安装 | 本次明确选择的组件已安装并完成相应检查 |
| 用户配置已保存 | 用户选择且明确要求应用的设置已写入，并已回读 |
| 运行条件已就绪 | 对应能力的配置和依赖检查通过；实际模型调用、PDF 解析与论文验收仍分别报告 |

### 6. 开始第一篇论文，找到输出

建议把 PDF 保存在**用户选定仓库内的 `Raw/`**，也可保留在其他稳定、可读取的位置。这里的 `Raw/` 始终相对于用户选定的仓库，不固定盘符或仓库名称。在以该仓库为工作目录的会话中提供 PDF 路径，例如：

> 用本库 APA 分析 `Raw/论文.pdf`，交付中英文 Obsidian 笔记。先检查配置和已有解析资料，再提出这次的来源范围、调用预算及截止时间，等我批准后执行；需要补充材料时先说明原因。

库外 PDF 请提供完整绝对路径。**文献 PDF 不要随意移动、改名或覆盖。** 分析开始后会绑定来源路径和文件指纹，后续续接与核验仍依赖这些记录；确需调整位置时，先确认受影响的运行与引用并安排迁移。

**调用 APA 时只提供 PDF 路径，不直接上传 PDF 本体。** 若用户将 PDF 作为附件发给 agent，agent 必须拒绝在当前会话启动分析，请用户先将文件保存在稳定位置，再新开会话提供路径，并说明这样做是为了避免 PDF 本体进入对话上下文、节省用量。不得先读取、提取或解析附件，也不得保存附件后在原会话继续分析。

把示例文件名换成实际文件名。首次任务由助手通过已接入的宿主适配器按项目技能组织执行，`npm run apa` 是底层工具入口，不是输入一个 PDF 就自动完成阅读的命令。配置通过也不代替这次运行的授权。

完成后，助手应给出**候选目录下中英文 Markdown 的实际路径**，以及本次完成情况和限制。以配置的候选目录为准；不要在空的 `Wiki/` 中寻找尚未正式发布的笔记。可在 Obsidian 中把此工程作为知识库打开，查看双语笔记、图表和知识链接。若中断，提供运行目录或检查点继续，不要重复重跑已完成内容。要进入正式 Wiki、默认检索和图谱，另行审阅并批准精确发布清单。

## 配置什么

| 配置 | 作用 |
| --- | --- |
| 运行宿主与派发 | 新运行冻结的子代理派发工具和参数名；只能采用 apa-setup 检测结果，换宿主后重新检测 |
| 科学角色默认模型及单角色覆盖 | 控制六个科学角色的实际模型与推理强度 |
| Writer、Translation、Editor、Verifier 模型 | 分别指定参数，或在新运行创建时跟随主会话并冻结 |
| 运行、解析、候选目录 | 当前库内的三个输出根目录，每次使用独立 run ID 子目录 |
| MinerU | 选择已有运行环境、Python 和配置文件 |
| 呈现方式 | 选择 Writer 与 Translation 直接呈现或增加 Reading Editor（新运行采用 reading-editor-1.1 版式，旧运行保持原版式） |
| Nature、Humanizer、stss | 分别启用已有技能，填写其 SKILL.md 路径；仅在既有 Writer 内使用 |

阅读和查询共用本库忽略提交的 `config/apa.local.json`，无需分别配置两套文件，无跨库全局层。公开包不含个人答案；已有运行继续使用原冻结绑定。详见 [配置说明](docs/CONFIGURATION.md)。

## 日常使用

- **分析论文**：“用 APA 分析 Raw/论文.pdf”。先核对已有材料，批准有限范围后执行。
- **继续任务**：“继续这次 APA 运行”，提供保存的运行目录或检查点。不会自动重做已完成内容或升级旧绑定。
- **调整设置**：“用 apa-setup 修改当前库配置”。支持完善、全部或选择去除、命名导出，以及导入前差异预览。去除答案不删除笔记或卸载依赖。
- **正式发布**：先审阅精确发布清单，再批准 V3 受控事务。候选完成不等于已发布。见 [发布接口](docs/apa-v3/reading-first-publication.md)。

### 查询与比较已入库论文

新分析按原文语言整理笔记：同语言稿放在 `Wiki/sources/`，另一语言稿放在 `Wiki/translations/`。两稿相互链接、按同一论文检索；中文原文会保留中文稿在 sources。旧冻结运行不自动改路径；已入库笔记需要受控迁移，不能直接拖动后跳过索引更新。

在 Codex 或已有本地工具能力的 Obsidian/Claudian 对话中，可以让助手“用 APA 在当前知识库查找某个主题”。两个入口使用同一条只读命令：

```powershell
node scripts/apa-query.mjs search --query "研究设计"
```

默认查询该脚本所在的知识库；选择其他获授权的库可加 `--vault-root "知识库完整路径"`。从其他工作目录调用时使用脚本完整路径。查询不要求 run ID、MinerU 或完整论文阅读配置，也不重新分析论文。

| 返回状态 | 含义 |
| --- | --- |
| `matches` | 找到已提交论文或专题；论文两语与共享节点按同一论文合并，专题单独标识并列出底层来源 |
| `no_matches` | 本次库内检索没有命中，不表示相关研究不存在 |
| `empty_library` | 当前有合法提交代次，但尚无论文 |
| `not_ready` | 尚无有效提交代次，或已提交内容的完整性检查失败 |

结果包含命中段落、笔记路径/锚点，以及已登记的书目和原文身份、可得定位。旧记录缺少出处时会明确提示，不自动补造 DOI 或页码。原文哈希匹配只证明文件身份；只有实际阅读对应原文后才能说关键论断已核对。

需要解释或比较时，可以直接在对话中提问，例如“库中这些研究的方法和适用条件有什么差异？请给出出处”。助手先检索，再由一个任务读取相关笔记、按需回看关键原文并回答；语言和详略跟随问题。同一论文的两语笔记不会算成两项证据，不可比的研究条件会分开说明。

APA 配置页设有独立的“知识库查询”页，可设置模型、默认回答语言、详略与讲解对象。当次明确要求优先；未设置偏好时跟随问题语言、按问题需要讲解。候选目录及 Nature、Humanizer、stss 写作指导复用已有配置，具体见[查询配置](.agents/skills/apa-query/references/configuration.md)。查询模型未设置时跟随当前会话；显式模型/推理强度必须由当前宿主确认支持，否则报告缺失能力，不自动换模型。只检查查询配置可运行 `node scripts/apa-setup.mjs inspect --capability query`；不要求 MinerU 或完整阅读设置，文件就绪也不表示模型已运行。

对接代理时，`request --input <JSON文件或->` 接收完整 `question` 与真实宿主能力，返回一个待执行任务；`-` 从 stdin 读取。现有搜索要求全部检索词命中，长问题可由当前任务提取简短的可选 `searchQuery`，例如问题“这些研究的设计与适用条件有何差异？”配合 `searchQuery:"研究设计"`；不提供时仍以原问题检索。返回的 `retrieval_query` 记录实际检索式，任务保留并回答完整原问题，不增加模型预处理或自动回退。当前任务符合配置时直接回答，需要其他模型时只派发一次支持的原生任务。`prepared` JSON 不是完成的答案。`source --paper-id <id> --generation-id <id> [--source-id <id>]` 用于取得同代次的登记原文位置。具体接线见 [apa-query 查询流程](.agents/skills/apa-query/references/query.md#search-and-answer-from-committed-papers)。

工程已覆盖配置、单任务接口和合成回归；2026-10-25已完成本机 Codex Desktop 与 Obsidian/Claudian Codex 的真实两论文问答验收；个人验收记录保留在本库 Eval 目录，不进入公开导出。两宿主分别跟随各自会话设置，不代表全部模型或provider组合已验证。Obsidian/Claudian 须有现有本地工具和所选模型调用能力，接口缺失时不能视为可用。查询保持只读；这次问答验收不包含专题保存与更新。

### 保存专题

希望保留某次回答时，可以明确说“把这个回答保存为专题”。助手会按提问语言准备一份 Obsidian 候选，保留回答正文，登记实际采用的论文、来源版本和出处。保存已有回答不强制再调用模型，也不要求生成另一语言版本。

专题具有独立身份和版本，正式路径为 `Wiki/topics/<topic_id>.md`。它是对已采用来源的综合，不增加独立论文数量。候选复用配置的 `paths.candidates`；普通查询不需要该路径，只有保存时才检查。助手负责整理实际采用来源，不能把所有搜索命中当作依赖，也不把来源哈希一致写成科学论断已经核验。

候选准备好后，助手展示正文、采用来源和精确发布清单。用户批准后才通过原 V3 事务提交专题、依赖和索引；随后可用原来的 `search` 检索。专题正文下的 `Personal Notes` 留给人工备注，更新时保留，机器检索不索引这部分内容。图谱建议只收录当前已提交专题，不自动修改 Obsidian 配置。

代理接口为 `node scripts/apa-query.mjs topic-save --input <JSON文件或->`；用 `topic-sources --topic-id <id> --generation-id <id>` 查看底层来源。候选经宿主注册后，审阅、精确批准、应用和恢复沿用 `scripts/v3/bilingual.mjs`，没有另一套专题发布命令。字段和接线见 [apa-query 专题保存流程](.agents/skills/apa-query/references/topics.md#save-a-topic-on-request)。候选准备、合成测试、真实宿主操作和生产发布分别记录。

### 按需更新专题

新论文正式入库后，系统根据已有术语和来源关系提示可能相关的专题。这一步不调用模型，也不改专题正文；无关论文不会使所有专题都变成“需复核”。可以先查看命中的术语与来源，再选择要纳入的内容。

明确选择来源后，助手使用现有查询模型配置执行一次更新任务，只读取原专题和所选新增或变化来源，生成正文及采用来源的差异候选。新版本保持原专题身份，经精确批准后提交；旧版本和人工备注保留。相关提示或更新答案本身都不授予发布权。

来源更正、替换或撤销需要明确记录原因，并沿原事务批准后才生效。提示只影响实际采用该来源版本的专题；“需复核”的专题仍可阅读和检索，同时显示原因。替换来源不会冒充原来采用的版本。更新时须说明对应处理，不能直接清空复核提示。

取消待发布操作会撤销该候选继续应用的资格，保留候选和当前正文。已提交的版本不能用“取消”撤回；正在发布或需要恢复的事务沿原恢复流程处理。专题更新的真实模型与宿主验收单独记录，不由合成测试代替。

代理接线使用 `topic-hints`、`topic-update-request`、`topic-update-candidate`、`source-change` 和 `topic-cancel`；输入、一次任务消费及受控发布步骤见[apa-query 专题更新流程](.agents/skills/apa-query/references/topics.md#update-a-saved-topic-on-request)。

## 更新与检查

更新前保留本地配置、论文、笔记和运行资料，检查工程文件的本地修改。按维护者提供的更新取得代码，依赖锁文件变化后运行 `npm ci`，再运行 `npm run setup:check` 和 `npm run apa:setup -- inspect`。工程更新不会自动安装可选依赖、同步全局技能或迁移旧运行。

`npm test` 运行工程附带测试；`npm run index:check` 检查现有提交索引，`npm run obsidian:graph:check` 检查图谱政策。空库没有已发表论文是正常状态。合成测试不能替代真实 PDF 解析、实际模型执行或 Obsidian 原生观察。

配置页过期时重新生成；缺文件时修正路径或按需安装；模型不可用时在派发前选择宿主支持的组合；换用其他 AI 助手宿主后重新运行 apa-setup 检测并更新派发方式，已开始的运行沿用原冻结设置。全局 APA 与工程不同步时可直接使用本库技能。排障见 [SETUP](SETUP.md)，科学要求见 [当前合同](docs/apa-v3/current-contracts.md)。

## 导出独立公开工程

配置导出与公开工程导出是两个独立操作。维护者运行：

```powershell
npm run apa:public:export -- --output .tmp/apa-public-setup/public
npm run apa:public:check -- --root .tmp/apa-public-setup/public
```

目标必须尚不存在。导出采用精确白名单，包含代码、合同、说明、合成测试、空知识库目录及相对路径/SHA-256 清单。它排除个人答案、论文、已有笔记/知识/图片、运行记录、缓存、本地环境、Obsidian 状态和 Git 历史，不清空本库。

检查后可独立审阅并决定新建公开仓库。导出不初始化 Git、不上传、不发布，也不决定软件许可。
